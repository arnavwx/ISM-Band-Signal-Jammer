# Reconstruction Audit

Before finalizing this repository, a complete audit of the available evidence was performed. This document details what was successfully recovered, what had to be reconstructed, and known limitations.

## Recovered Artifacts
- **Component List**: `Components_Electroboom_EW1.pdf` was recovered intact.
- **Hardware Architecture**: The whiteboard sketch `IMG-20251017-WA0007.jpg` was recovered and analyzed for SPI pinouts.
- **Experimental Media**: Several `.mp4` video files were recovered showing the device in operation.
- **Team Communications**: The WhatsApp chat log was fully recovered, providing the crucial context needed to understand the pivot from a 555-timer design to an ESP32 design, as well as the GitHub repositories used for inspiration.

## Reconstructed Artifacts
- **Source Code (`src/main.cpp`)**: The original source code files were lost. A clean implementation was written from scratch using the `RF24` library to mirror the intended functionality (rapid frequency sweeping with dual radios).
- **Documentation (`README.md`, `docs/*`)**: The final submitted paper was not present in the supplied archives. All documentation was generated by synthesizing the chat logs, component lists, and video evidence.
- **Build System (`platformio.ini`)**: The build environment was reconstructed using standard PlatformIO configurations.

## Missing Artifacts
- **Final Project Report/Paper**: Not present in the provided ZIP archives or the user's workspace.
- **Original Source Files**: No `.ino`, `.cpp`, or `.h` files survived.
- **Detailed OLED Wiring**: The whiteboard diagram omitted the OLED display. Standard I2C pins were inferred.

## Validation Performed
- **Hardware Mapping**: The reconstructed code in `main.cpp` maps perfectly to the pinouts shown in the recovered whiteboard diagram (CE1=4, CSN1=5, CE2=2, CSN2=15).
- **Dependency Checks**: The `platformio.ini` file includes the exact libraries needed to compile the code (`RF24`, `Adafruit SSD1306`).
- **Sanity Checks**: The code's channel sweeping math `(ch + 40) % 84` successfully utilizes the dual-radio setup to cover the 2.4GHz band efficiently, matching the architectural intent.

## Known Limitations
The effectiveness of this reconstructed firmware relative to the original cannot be empirically tested without physical hardware. The original team may have tweaked timing delays or PA levels (Power Amplifier) in ways not documented in the chat logs. The current firmware provides a solid, theoretically sound baseline for 2.4GHz jamming using the specified components.
